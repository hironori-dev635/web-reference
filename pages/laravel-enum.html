PHP 8.1 の Enum を Laravel のカラム・バリデーション・Blade で使うときの最短ルート。

定義

namespace App\Enums;

enum PostStatus: string
{
    case Draft = 'draft';
    case Published = 'published';
    case Archived = 'archived';

    public function label(): string
    {
        return match ($this) {
            self::Draft => '下書き',
            self::Published => '公開',
            self::Archived => 'アーカイブ',
        };
    }
}
書き方 結果
PostStatus::Draft Enum 本体
PostStatus::Draft->name 'Draft'（ケース名）
PostStatus::Draft->value 'draft'（DB に入れる値）
PostStatus::from('draft') 無ければ例外
PostStatus::tryFrom('nope') 無ければ null
PostStatus::cases() 全ケースの配列

enum Foo: string / : int が Backed Enum。value を持たない Pure Enum は DB 保存には向かない。

Eloquent の cast

protected $casts = [
    'status' => PostStatus::class,
];
$post->status = PostStatus::Published;
$post->save();

$post->status === PostStatus::Published; // true
$post->status->value;                    // 'published'
$post->status->label();                  // '公開'

DB には draft のようなスカラーが入る。モデル上では Enum として取り出せる。

バリデーション

use Illuminate\Validation\Rule;

$request->validate([
    'status' => ['required', Rule::enum(PostStatus::class)],
]);

フォームの select はだいたいこれ。

@foreach (PostStatus::cases() as $status)
    <option value="{{ $status->value }}"
        @selected(old('status', $post->status?->value) === $status->value)>
        {{ $status->label() }}
    </option>
@endforeach

クエリ

Post::where('status', PostStatus::Published)->get();
Post::where('status', PostStatus::Published->value)->get();

どちらでも動くことが多い。比較や whereIn で迷ったら ->value を明示したほうが事故が少ない。

Post::whereIn('status', [
    PostStatus::Draft->value,
    PostStatus::Published->value,
])->get();

忘れやすいポイント

  • マイグレーションのカラムは string か unsignedTinyInteger。DB 側に PHP Enum は作れない（MySQL の ENUM 型とは別物）。
  • Blade で {{ $post->status }} はオブジェクト。表示するなら ->value か ->label()。
  • JSON レスポンスに Enum をそのまま出すと {"name":"Draft","value":"draft"} になりがち。Resource で $this->status->value に寄せる。
  • from() は不正値で例外。tryFrom() は null。入力値は tryFrom か Rule::enum。
